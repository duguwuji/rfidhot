# RFID 热点：配置与上线交接

站名为 RFID 热点，MCP 前缀 `rfidhot`，采集标识 `RFIDHOTBot`。沿用原框架的采集、预算熔断、双次评分、事件归组和统一发布层。十二小时抓取间隔通过增量迁移更新已有信源，不更改依赖。

## 编辑口径

按技术产品、应用部署、企业动态、标准法规、研究方法五类浏览。重视可核验的芯片/标签/读写器参数、测试条件、部署阶段与规模、标准版本及生效日期；压制空泛宣传、无增量转载和与 RFID 无关的通用科技消息。

区分 RAIN RFID、HF/NFC 与 Ambient IoT 的链路和能源机制；无电池不自动等于无源 RFID。DPP/PPWR 不自动等于强制采用 RFID。库存真值、补货预测和 ROI 需保留来源、指标口径及厂商归因。评分保留原有七类型、五维权重和安全边界。

## 新站与已有站点

新站按 [部署](deploy.md) 初始化环境，运行原始迁移与 `scripts/seed.ts`。站点地址由 `SITE_URL` 配置；模型由 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL` 配置。密钥不能入库或提交到 Git。

已有站点的信源不会被 seed 覆盖，也不会自动停用旧 AI 信源。应先关闭采集与模型安全阀，备份数据库，在后台停用旧信源并审核旧公开内容；推荐为 RFID 新站使用独立数据库。运行 seed 更新 RFID 主题后，在后台验证新信源配置。主题导入不会自动删除原有目录，因此旧主题也需在备份后由数据库管理员审核清理（当前没有主题管理界面）。不要将旧 AI 新闻误呈现为 RFID 新闻。

2026-09-29 的首批配置验证未启动 worker、未采集运营数据、未部署线上服务。当前部署见 [Google Cloud 部署](google-cloud.md)；开发验证仍使用独立空库，采集、模型、飞书推送与 IndexNow 保持关闭。

## 上线前需要运营者决定

1. 填写域名、运营主体、联系邮箱、反馈处理方式，必要时填写 ICP；确认使用规则、隐私说明、日志服务及保留期限。`industry/pages/` 仍明确标为待确认草稿。
2. 配置模型接口与预算，核对时区和每天北京时间 08:00 日报安排；信源试抓完成后再开启相应安全阀。
3. 标注 100–200 条真实 RFID 材料，按 [精选校准](selection.md) 评估后再决定门槛。当前 T1 60 / T1_5 65 / T2 76、预筛分数下限 50 仅保留原始基线，尚未验证 RFID 选稿准确率。
4. `gold.example.jsonl` 与 `relation-gold.example.jsonl` 全部是虚构格式示例，不能充当运营者标注集或效果证据。

品牌图标使用独立 R 字形与射频弧线，日报/周报/月报报头已重新生成。字体许可见 `industry/brand/FONT-NOTICE.md`。模型榜与 Codex 重置监控关闭，其导航和公开接口不再提供。
