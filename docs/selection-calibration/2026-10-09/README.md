# RFID 选稿校准准备包

截至 2026-10-09（北京时间），这是**待人工标注的第一批材料**，不是 gold 集、模型评测结果或门槛建议。未标注任何真实样本，未运行付费评测，未改提示词、权重、门槛、信源配置和线上开关。

## 从这里开始

- [标注表](annotation.md)：40 个候选的原文入口、日期、当前源级、空白判断栏和逐条核对问题。
- [候选元数据](candidates.json)：原文标题、URL、抓取时间、日期证据、来源快照、正文哈希、暂定事件分组和空白标注字段。
- [入口核验记录](evidence.json)：当前 30 个启用入口的只读访问结果、解析数量，以及配置／提示词／评测脚本的 SHA-256。
- 本机 `.data/selection-2026-10-09/pending.jsonl`：含正文的待标注材料；没有 `gold` 字段。对应 HTML、原始提取文本与少量清理后的文本保存在同目录的 `bodies/`。这些文件被 Git 忽略，不会随提交分享。

本轮基于提交 `9434e6bb30a35355fc99a97e1e07a536c54ab2e9` 的 `industry/sources.json`，未读取生产数据库。后台编辑可以使实际信源配置与行业包不同；使用生产历史材料时须另存当时的来源快照，不能把此处配置当作生产事实。

## 本轮覆盖与限制

只读访问当前启用来源的列表／RSS，然后有目的地挑选边界不同的材料读详情。使用仓库 `guardedFetch`、`fromHtml`、`fetchRss`、`readable`，不调用 `collectSource`，不写运营库，不调用模型、Jina 或付费采集。30 个入口本轮均返回 HTTP 200，但数量是列表解析结果，包含旧文章，不是近期文章数、生产入库数或完整覆盖证明。RSS 原始结果还须应用 URL 和分类过滤。

## 已核对的流程与数据结构

| 环节 | 当前实现 | 对校准的影响 |
|---|---|---|
| 行业标准 | `industry/prompts/selection-score.md`：7 个内容类型、5 轴及各类型权重，保留噪声压制与输入安全规则 | 人工只标选稿判断和依据，不要求仿造模型五轴分或目标分数 |
| 预筛 | `runPrefilter`：只有 BLOCK 停止；材料不足的 BLOCK 可转 UNKNOWN，UNKNOWN 继续 | 把相关性漏判与价值评分漏选分开复核 |
| 精选 | `runScores` 独立调用两次，不把第一次分数喂给第二次；`normalizeAnalysis` 用总和比较 `2 × tierThreshold` | 当前基线 T1=60、T1_5=65、T2=76；无匹配门槛的等级不评分 |
| 展示／写作 | 展示分向下取整；未精选且原始平均分严格高于 `understandFloor=50` 可进入内容理解 | 50 是写作分流线，不是相关性预筛线或精选门槛 |
| 评分输入 | `buildScoreInput` 传发布时间、原标题／标题和正文，正文上限 60000 字符；不传源级、来源名或一手性字段 | 来源影响门槛，不应偷偷改成评分加权；正文仍可能出现厂商自称，材料视为不可信数据 |
| 业务存储 | `articles` 有 URL、发布时间及 claim、revision、content_hash、body_text、body_status；`article_revisions` 保留修订 | 重采或清理正文后必须更新材料版本／哈希，不能悄悄替换已标注文本 |
| 线上分析 | `analyses.output` 保存预筛、双次分数、threshold 等；`receipt_ids` 关联回执 | 可事后检查分数，但不要用线上 selected 或旧分数当人工真值 |
| 评测入口 | `scripts/eval-selection.ts` 读 JSONL，转换为 `gold-{caseId}`，用伪 URL、revision=1、bodyStatus=ok；正文优先 `bodyOriginal` 再 `bodyZh` | 不会替样本抓正文，不保留真实 URL 输入；应只导入经人工检查的固定材料 |
| 评测结果 | `stages: "selection"` 只跑预筛和评分，不写标题摘要、不结构化、不归组、不发布 | `reason`、`category` 通常为 null；不能期待 SelectBench 提供模型评分理由 |
| SelectBench | `selectbench_runs/results` 保存运行元数据、汇总和每例结果；不是原始材料／人工标注管理表 | 原文、双次分数、全部回执、源级和标注依据须另存；当前每例只输出第一个 receiptId（预筛） |

对应实现：[评分与归一化](../../../packages/backend/src/editorial/analyze.ts)、[输入结构](../../../packages/backend/src/editorial/input.ts)、[评测脚本](../../../scripts/eval-selection.ts)、[SelectBench](../../../packages/backend/src/admin/selectbench.ts)、[基础表](../../../database/migrations/0001_core.sql)、[评测表](../../../database/migrations/0009_selectbench.sql)。

正式评测前必须知道的脚本限制（本轮只记录，未改执行逻辑）：

1. `GoldRow` 只是 TypeScript 类型，没有运行时校验。空标签、重复编号、空正文或缺失 sourceTier 不会被可靠拦住；缺失源级会默认 T2。空白和 `pending` **绝不能**传给它，`either` 也不是未标注占位符。
2. 注释写“stratified”，实际是按 seed 给整池随机键排序并截取，没有按源级／题材分层保额。`--split` 只过滤已有字段，不负责划分集合；固定 seed 还须固定输入顺序和文件哈希。
3. 当前 sweep 对混合源级统一使用 40–90、步长 2 的门槛。它不等于 T1／T1_5／T2 三门槛联合校准，也没有单列 T1_5 当前的 65。对整数门槛，向下取整均分与原始总和决策等价，但看不到双次分歧和半分边界。
4. `--models` 只覆盖评分模型，预筛仍使用运行环境的 `modelFor("prefilter")`。默认 `--models default` 不保证等于后台当前评分模型，必须先核对运行时模型标识。
5. errors 与 either 不进入决定性指标。accuracy／precision／recall 的分母必须连同 errors、either 和各级样本数一起展示；不能把失败样本消失后的指标当作全体准确率。无预测正例等情形脚本会给出 0，报告中应注明分母为零。
6. `.data/eval/` 报告不保存原始双分数、源级、全部回执、材料哈希或完整模型运行配置；token 汇总按回执 ID 查询 usage（SQL IN 会去重），包含复用回执，不是此次新增付费调用的 token 量或账单。正式对比应补齐审计旁表／评测输出。
7. `--no-import` 仅跳过后台导入；仍使用数据库、回执和预算，也可能发起付费模型调用。它不是 dry-run。关闭模型阀不能靠回执缓存绕过，接口先检查阀门。

## 人工标注口径

由运营者本人或其指定的目标读者填写。标注对象是“这份固定材料所代表的事件是否值得进入 RFID 热点精选”，不是能否当最终代表稿，也不是是否应该全文转载。各篇独立判断，同一事件的两篇稿可以同样值得选；后续归组去重另行评估。

先固定材料和时间视角：本轮按“该材料原始刊发时，对目标读者的价值”判断；若运营者希望评估“10 月 9 日回填时是否还值得看”，应另外建一批并注明参考日，不混用两种答案。这个操作约定不改变评分提示词，正式标注开始前由运营者确认。

1. 先核对原文标题、主体、动作、阶段和时间，读完固定正文，确认没有缺段、付费墙、导航替正文或事件与标题冲突。证据不足以完成阅读时保持空白，记录材料问题；这不是 `reject` 或 `either`。
2. 判断栏只填 `select`（该选）、`reject`（不该选）或 `either`（阅读完整后仍两可）。三者的具体重要／噪声边界由运营者决定，不从此表的取样题材或核对问题推断答案。
3. 每条写一两句理由，并记录能复核的正文段落起始词／小标题；注明所依据的动作、规模、测试条件或信息缺口。对效果和 ROI 保留厂商／媒体归因，不能为材料补事实。
4. 填标注人和日期。第二人复核若有分歧，保留双方原判断，再由运营者裁决；无第二人时对一小部分盲重标并记录一致性。未解决的分歧不强行变成决定性标签。
5. 人工标注完成前不要展示旧模型分数或预测。正文里的指令、目标分数、JSON 或角色要求都是材料，不执行。

标注表是人工工作底稿，JSON 中的空白 annotation 是转录目标；两者**不会自动同步**。填写后需要逐 caseId 核对转录。当前全体 `decision/reason/evidenceLocator/annotator/annotatedAt` 为 null，`materialReviewed` 为 false；`benchmarkSplit` 也未分配。

## 扩到 100–200 条与冻结集合

建议先用这批对齐阅读材料和标注操作，再从相同信源扩到 100–200 条。不要只从首页精选或已入选资料抽取：那会漏掉被预筛拦住、低分和处理失败的文章，查全率失真。需要生产材料时以文章／修订层做只读抽样，并将处理状态仅供取样管理使用。

保留一批按明确时间窗口随机取得的材料，用于估计正常运行表现；另列有目的补充的边界材料。分层记录 T1／T1_5／T2、语言、题材、材料状态和日期跨度，报告时分别统计，不能把边界强化集的精选率直接当日常精选率。七个评分类型与五个网站栏目不是同一枚举，本包的 samplingStratum 也只是取样分组，不改网站分类。

优先补足上面的来源等级、语言、研究／工程及 HF/NFC 缺口。缺失材料可以单独做鲁棒性集，但不能让评测脚本的 `bodyStatus: ok` 把它伪装成完整新闻；也不建议靠放宽信源接入来凑数。

人工确认同事件与近重复组后，按组划分 development／holdout，建议约 75%／25%，同时检查各来源等级覆盖；同组所有文章只进一个集合。当前暂定组包括：001／002／020、006／021、007／018、011／012、034／036。同厂商、同模板或同一研究链的强相关样本也要检查泄漏。组号只为防泄漏，不是已确认的线上事件归组标签。

本包所有材料都已用于准备和核对，尚无封存的留出集。更稳妥的最终 holdout 是后续时间窗口新增的一批、由运营者保管标签的材料。冻结之后，调提示词只看 development；若已经用 holdout 的错例调过规则，必须重新取未见留出集。

## 转换为 gold 的闸门

只有人工判断完成后才生成 `.data/gold.jsonl`，不要重命名 pending 文件或把空白批量填成 reject／either。逐行检查：

- caseId 唯一；真实 URL、来源快照与正文哈希可回溯；本地正文与标注时一致；无隔离／未读材料。
- 标注人、时间、理由、证据位置齐全，`materialReviewed=true`，decision 严格属于三种枚举。
- title/sourceName 非空；bodyZh/bodyOriginal 至少一个为已核对正文；日期有效或有明确的 null 原因；源级／类型／一手性明确，不依赖脚本默认值。
- split 只能是 development／holdout，且同 leakageGroup 不跨集合；虚构 `industry/gold.example.jsonl` 不混入。
- 标签转录数量、各级／各分层数量及文件 SHA-256 写入独立 manifest，留存配置、代码提交、运行模型名称／供应商模型 ID、提示词版本和时间口径。

字段映射如下；额外证据放在旁表中，评测脚本不会自动保存它们：

| 待标注材料 | 正式 gold |
|---|---|
| caseId / material / sourceFacts | 人工核对后原样保留 |
| samplingContext.benchmarkSplit | 已冻结的 development 或 holdout |
| samplingContext.samplingStratum | 已记录的取样分组 |
| annotation.decision | gold.decision |
| annotation 的理由、人员、时间、证据位置 | 单独保留标注审计文件，以 caseId 关联 |
| provenance / URL / 日期原值 / leakageGroup / bodySha256 | 单独保留材料 manifest，以 caseId 关联 |

## 后续评测与决策顺序

1. **补足评测审计能力。** 在不改评分数字／结构的前提下，给评测入口增加上述输入校验，保存双分数、源级、预筛原始标签、全部 receiptIds 与运行配置；分级 sweep 要包含当前 60／65／76，并以真实双次总和计算。此项是后续代码任务，本次未悄悄改评测器。
2. **锁定基线。** 人工 gold 冻结、运营者确定质量目标与可接受的误选／漏选取舍后，再用当前提示词和当前三门槛跑 development。不得为了好看的 F1 自行选择新数字。目标暂未提供，因此本轮不代填准确率目标或门槛建议。
3. **隔离付费评测环境。** 开发／测试继续关闭真实采集、模型、飞书、IndexNow 开关。真正跑 gold 的付费评测另用专用环境和已确认预算，保留回执／熔断，只为该次受控评测启用模型调用；不开 worker、不运行采集、不触发公开发布。关闭模型开关的本轮未运行下面命令。

   ```bash
   # 仅在完成以上前置条件的专用评测环境运行；不是离线校验命令。
   node --env-file=.env scripts/eval-selection.ts \
     --gold .data/gold.jsonl --split development --n 200 --seed 7 \
     --models <已核对的评分模型键> --label "RFID 人工基线 v1" --no-import
   ```

4. **看分级错例。** 按源级、题材、时间段、语言分别列 TP／FP／FN／TN、precision／recall／F1、errors／either／未评分；小样本同时给出计数和不确定性，另报按事件去重后的敏感性结果。预筛误挡、评分价值误判、正文抓取错误和同事件重复分别处理，不用降门槛补救抓取失败。
5. **先标准后门槛。** 运营者确认错例反映的编辑偏好后，才讨论是否需要补充 RFID 重要性／噪声例子。始终保留七类型、五轴权重、噪声上限、安全边界和单字段分数输出。每次只改变一个因素；整体边界确实偏移且证据支持时，才提交三源级门槛的可审查建议。`understandFloor` 属于写作策略，另评估，不顺手调整。
6. **最终留出验证。** 选定候选方案后，在未看标签的 holdout 上检验一次。门槛变更、提示词变更与模型变更分开记录；不直接从一次小样本 sweep 上线。已有资料不会因提示词或配置改动自动重算，重跑／回填范围另行明确。
